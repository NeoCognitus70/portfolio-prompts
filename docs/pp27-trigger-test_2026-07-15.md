The exact command used to start the session (and therefore how the plugin was loaded) is not
present in the transcript. Future PP-27 runs should open with the tester quoting the command line
explicitly so it can be recorded verbatim.

### 2. Negative test for `loop-all-worklists` not performed

As noted above, no adjacent probe for the mutating skill was attempted. PP-27's success criterion
explicitly requires confirming explicit-invocation-only behaviour; that half of the criterion is
unverified by this session. Suggested action: in the same or a follow-up session, send a natural
phrasing such as "action all the worklists for every project" and confirm the skill does **not**
auto-fire without an explicit `/portfolio-prompts:loop-all-worklists` invocation or equivalent
skill-tool call. If it does auto-fire, the skill description needs a stronger negative trigger
guard.

### 3. `portfolio-prompts:portfolio-status` delivered inline, not to a file

The skill fired correctly for the natural request. The tester then had to issue a second message to
get a file. Whether that is intended behaviour (report in chat by default, file on request) is
correct per the prompt spec — `portfolio-status.prompt.md` says nothing about writing to a file
unprompted. No description tweak needed; documenting for clarity.
